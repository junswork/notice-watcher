# 내 서버에서 돌리기 (자가 실행기)

깃허브 공용 실행기는 전 세계가 나눠 쓰는 풀이라 바쁠 때 줄을 선다. 1분 간격으로
돌리자 **하루 실행의 81% 가 취소**되고 에픽폴리오가 37시간 동안 확인되지 않은
날이 있었다. 취소는 실패로 잡히지 않아 아무 경보도 울리지 않았다.

그래서 실행기만 내 것으로 바꿨다. **나머지는 전부 그대로다** — 코드, 상태 저장,
Secrets, 알림, cron-job.org 설정 모두.

## 지금 구성

| | |
|---|---|
| 서버 | Oracle Cloud 무료 티어, 도쿄(ap-tokyo-1) |
| 사양 | VM.Standard.E2.1.Micro — 1/8 OCPU, 1GB (+ 스왑 2GB) |
| OS | Ubuntu 24.04 (파이썬 3.12 기본 포함) |
| 실행기 이름 | `oracle-tokyo` |
| 접속 | `ssh -i ~/.ssh/oracle-notice-runner.key ubuntu@<공용IP>` |
| 저장소 | **비공개** |

## 왜 저장소를 비공개로 바꿨나

깃허브 공식 경고다.

> 포크된 공개 저장소가 풀 요청을 통해 자체 호스팅 실행기 머신에서 위험한 코드를
> 실행할 가능성이 있습니다. 자체 호스팅 실행기는 **비공개 저장소와만** 함께
> 사용할 것을 강력히 권장합니다.

공개로 두면 누구나 포크해서 악성 워크플로가 담긴 PR을 보내 이 VM 에서 실행할 수
있다. 비공개로 바꾸면 그 경로가 막힌다.

무료 사용 시간은 걱정하지 않아도 된다. **자가 실행기로 돌린 작업은 월 2000분
한도에 계산되지 않는다.** 비공개 저장소를 권하는 이유가 여기 있다.

## 어디서 돌지는 변수 하나로 정한다

워크플로에 실행기를 못 박지 않았다.

```yaml
runs-on: ${{ vars.RUNNER_LABEL || 'ubuntu-latest' }}
```

커밋 없이 오갈 수 있다.

```bash
# 내 실행기로
gh variable set RUNNER_LABEL --body self-hosted --repo <계정>/notice-watcher

# 깃허브 공용으로 (되돌리기)
gh variable set RUNNER_LABEL --body ubuntu-latest --repo <계정>/notice-watcher
```

변수가 없으면 공용 실행기를 쓴다 — 새로 받아 쓰는 사람이 아무것도 설정하지
않아도 돌아가야 한다.

## 되돌리는 법

문제가 생기면 **1분이면 원상복구**된다. 순서대로 한다.

```bash
# 1. 공용 실행기로 되돌린다 (즉시 반영)
gh variable set RUNNER_LABEL --body ubuntu-latest --repo <계정>/notice-watcher

# 2. 저장소를 다시 공개로 (공용 실행기는 공개여야 시간 무제한)
gh repo edit <계정>/notice-watcher --visibility public \
  --accept-visibility-change-consequences
```

그리고 **cron-job.org 작업 1을 2분으로 늘린다.** 공용 실행기에서 1분은 대기가
쌓여 취소를 부른다.

VM 은 그냥 두거나 지우면 된다. 실행기 서비스만 멈추려면 VM 에서:

```bash
cd ~/actions-runner && sudo ./svc.sh stop
```

## 파이썬을 따로 설치하지 않는다

처음 옮겼을 때 한 번 도는 데 **116초**가 걸렸다. 공용 실행기에서는 14~24초였다.
단계별로 재 보니 `setup-python` 이 **76초**를 먹고 있었다.

공용 실행기에는 파이썬이 미리 받아져 있지만 내 실행기에는 없어 매번 내려받는다.
그런데 우분투 24.04 에는 파이썬 3.12 가 이미 들어 있다. **그 단계 자체가 필요
없었다.**

라이브러리는 홈 디렉터리의 가상환경(`~/.venv-notice`)에 한 번만 깔고 다음
실행부터 그대로 쓴다. **작업 폴더 안에 두면 안 된다** — `checkout` 이 매 실행마다
`git clean -ffdx` 로 작업 폴더를 비우기 때문에 그때마다 지워진다.

## 메모리가 1GB 뿐이라 스왑을 만들었다

실행기(.NET)와 파이썬이 동시에 뜨면 빠듯하다. 2GB 스왑을 붙여 두었다.

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

## 고장 났을 때

**VM 이 단일 장애점이다.** 공용 실행기는 죽으면 다른 것이 받지만 내 VM 은 그렇지
않다. 실행기 서비스가 멈추면 감시도 멈춘다.

알아채는 경로:

- **아침 생존 신호가 안 온다** — 가장 확실한 신호
- 생존 신호에 `지난 하루 실행` 줄이 붙는다. 취소가 많으면 빨갛게 바뀐다
- 깃허브 Actions 탭에서 실행이 `queued` 로 쌓여 있으면 실행기가 죽은 것이다

VM 에서 확인하고 되살리는 법:

```bash
cd ~/actions-runner
sudo ./svc.sh status     # active (running) 인지
sudo ./svc.sh start      # 멈췄으면 다시 시작
sudo journalctl -u actions.runner.<계정>-notice-watcher.oracle-tokyo.service -n 50
```

재부팅해도 자동으로 뜨도록 등록해 두었다(`systemctl is-enabled` → `enabled`).

## 실행기를 다시 설치해야 할 때

등록 토큰은 1시간만 유효하므로 그때그때 새로 발급한다.

```bash
# 내 PC 에서 토큰 발급
gh api -X POST repos/<계정>/notice-watcher/actions/runners/registration-token --jq .token

# VM 에서
cd ~/actions-runner
./config.sh --unattended --replace \
  --url https://github.com/<계정>/notice-watcher \
  --token <발급받은 토큰> \
  --name oracle-tokyo --labels self-hosted,linux,x64 --work _work
sudo ./svc.sh install ubuntu && sudo ./svc.sh start
```

## SSH 키는 저장소 안에 두지 않는다

내려받은 키를 저장소 폴더에 두면 그대로 커밋된다. 공개 저장소였을 때 한 번
올라갔다면 누구나 이 서버에 들어올 수 있다. `.gitignore` 에 `*.key`, `*.pem`,
`id_rsa*` 를 넣어 두었지만, 애초에 `~/.ssh/` 에 두는 것이 맞다.
