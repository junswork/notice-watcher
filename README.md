# 공지사항 알림이

서울과학기술대학교 공지사항 게시판에 **새 글이 올라오거나 기존 글이 수정되면**
카카오워크로 알려준다.

감시 중인 게시판:

| 이름 | 주소 |
|---|---|
| 대학공지사항 | https://www.seoultech.ac.kr/service/info/notice/ |
| 학사공지 | https://www.seoultech.ac.kr/service/info/matters |
| 생활관 공지 | https://housing.seoultech.ac.kr/community/notice |
| 에픽폴리오 비교과 | https://epic.seoultech.ac.kr/ptfol/imng/icmpNsbjtPgm/findIcmpNsbjtPgmList.do |

## 컴퓨터를 켜놔야 하나?

**아니다.** 깃허브 서버에서 알아서 돈다. 노트북을 닫아도, 여행 중이어도 알림은
온다. 이 프로그램은 브라우저를 띄우지 않고 페이지만 받아 읽기 때문에 어디서
돌든 상관이 없다 (예매 프로그램과 다른 점이다). 얼마나 자주 도는지는 아래
'언제 얼마나 자주 도나' 를 보라.

## 어떻게 알아채나

학교 게시판 세 곳(대학공지·학사공지·생활관)은 모두 같은 게시판 프로그램을
쓴다. 목록의 링크는 전부 `?do=commonview...&bidx=숫자` 꼴이고, `bidx` 가
게시물의 고유 번호다. 그래서 파서 하나로 셋을 처리한다.
에픽폴리오만 다른 시스템이라 따로 다룬다(맨 아래 참고).

확인을 두 가지로 나눠 놓았다.

**새 글 확인** — 목록 한 번만 받는다. 처음 보는 번호가 있으면 그 글의 상세만
열어 제목을 읽고 알린다. 평소에는 새 글이 없으니 게시판당 접속이 한 번이다.
가볍기 때문에 자주 돌린다.

**수정 확인** — 목록에 걸린 글의 상세를 전부 다시 읽어 **제목·작성자·날짜·
첨부파일·본문**을 하나의 지문(해시)으로 만들고, 지난번 지문과 비교한다.
게시판당 접속이 스물몇 번이라 하루 두 번만 돈다.

**왜 상세 페이지까지 받나.** 이 게시판에는 '수정일' 항목이 없다. 본문만 고쳐도
목록에 보이는 제목과 날짜는 그대로다. 목록만 봐서는 수정을 알아낼 방법이 없다.

**조회수는 지문에 넣지 않는다.** 조회수는 누가 열어볼 때마다 바뀌므로 넣으면
매번 '수정됨' 알림이 온다. 실제로 조회수가 595 → 599 로 오르는 동안 지문이
그대로인지 확인해 두었다 (`test_hash_ignores_views`).

**놓치지 않기 위한 규칙 두 가지.**

- 알림을 먼저 보내고, **보내는 데 성공한 것만** 기록에 남긴다. 순서를 뒤집으면
  전송이 실패했을 때 그 공지는 영영 다시 알려주지 않는다.
- 게시판 한 곳이 접속에 실패해도 그 게시판의 기록은 건드리지 않는다. 다음
  실행에서 다시 확인한다.

**첫 실행은 조용하다.** 처음 돌면 지금 걸려 있는 것이 전부 '새 글'이라 알림이
수십 건 쏟아진다. 그래서 게시판마다 첫 실행은 기록만 하고 알리지 않는다.
게시판을 새로 추가했을 때도 마찬가지다.

## 처음 한 번 설정하기

### 1. 깃허브 저장소 만들기

이 폴더를 깃허브에 올린다. **공개(Public) 저장소를 권한다** — 공개면 Actions
사용 시간이 무제한이다. 비공개면 무료 월 2000분 한도가 있어 15분 주기가 한도를
넘는다 (아래 '언제 얼마나 자주 도나' 참고). 이 폴더에는 비밀이 될 만한 것이 없다.
열쇠는 코드가 아니라 깃허브 Secrets 에 넣는다.

```bash
cd "c:/0/Workspace/공지사항 알림이"
git init
git add .
git commit -m "공지사항 알림이"
gh repo create notice-watcher --public --source=. --push
```

`gh` 가 없으면 깃허브 웹에서 저장소를 만들고 `git remote add origin ...` 후 push.

### 2. 워크플로에 쓰기 권한 주기

**이걸 안 하면 같은 알림이 계속 온다.** 확인 결과(`state.json`)를 저장소에
되커밋해야 다음 실행이 "이미 알린 공지" 를 구분하는데, 새 저장소는 기본이
읽기 전용이라 그 커밋이 실패한다.

```bash
gh api -X PUT repos/<계정>/notice-watcher/actions/permissions/workflow \
  -F default_workflow_permissions=write
```

웹에서 하려면 Settings → Actions → General → Workflow permissions →
**Read and write**.

### 3. 열쇠 등록하기

`gh` 로 넣는 게 빠르다. **깃허브 Secrets 는 한 번 저장하면 값을 다시 볼 수
없다** — 화면에 이름만 나오고 값 칸이 비어 보이는 것이 정상이다.

```bash
gh secret set KAKAOWORK_APP_KEY_NOTICE --repo <계정>/notice-watcher
# 값을 붙여넣고 엔터
```

| 이름 | 값 |
|---|---|
| `KAKAOWORK_USER_EMAIL` | 본인 카카오워크 이메일 (모든 봇 공통) |
| `KAKAOWORK_APP_KEY_NOTICE` | 대학공지사항용 봇 앱키 |
| `KAKAOWORK_APP_KEY_MATTERS` | 학사공지용 봇 앱키 |
| `KAKAOWORK_APP_KEY_HOUSING` | 생활관 공지용 봇 앱키 |
| `KAKAOWORK_APP_KEY_EPIC` | 에픽폴리오용 봇 앱키 |
| `EPIC_ID` / `EPIC_PW` | 학교 통합 계정 (에픽폴리오 로그인용) |
| `KAKAOWORK_APP_KEY` | (선택) 공용 봇. 전용 봇이 없는 게시판이 이걸 쓴다 |

게시판별 봇을 다 만들 때까지는 `KAKAOWORK_APP_KEY` 하나만 넣어도 돌아간다.
전용 봇을 만드는 대로 하나씩 추가하면 그 게시판부터 새 봇으로 넘어간다.

넣은 값이 실제로 들어갔는지는 실행 로그로 확인한다. 설정된 Secret 은 로그에
`***` 로 가려져 나오고, 안 넣은 것은 빈칸으로 남는다.

### 봇을 새로 만들려면

카카오워크 관리자 사이트 → **봇 관리** → **Bot 개발** → **Bot 생성하기**.

필수 입력은 **이름 / 한 줄 설명 / 문의** 세 가지뿐이다.
**Request URL 과 Callback URL 은 비워 둔다.** 그 둘은 사용자가 버튼을 눌렀을
때 우리 서버로 이벤트를 받기 위한 것이다(`submit_action`, `call_modal`).
이 프로그램은 보내기만 하고 받지 않으므로 필요 없다.

앱키는 봇을 만들면 자동으로 나온다. **Bot 기본 정보** 탭에서 확인해 복사한다.

### 4. Actions 켜고 한 번 돌려보기

저장소 → **Actions** 탭 → 워크플로 실행 허용 → 왼쪽에서 **공지사항 감시** 선택
→ **Run workflow** 를 눌러 손으로 한 번 돌린다.

첫 실행은 알림 없이 기록만 남기는 것이 정상이다. 로그에
`첫 실행 — 게시물 N건을 기준으로 저장합니다` 가 보이면 성공이다.
그 다음부터는 정해진 일정대로 저절로 돈다.

> 예약 실행은 깃허브가 바쁠 때 몇 분 늦게 돈다. 적어 둔 주기는 최소 간격이지
> 보장 시각이 아니다. 공지사항은 초를 다투는 일이 아니므로 문제되지 않는다.

## 로컬에서 확인하기

```bash
pip install -r requirements.txt
cp .env.example .env      # 그리고 열쇠를 채운다

python test_watch.py          # 자체 점검 (네트워크 불필요, 10건)
python test_watch.py --live   # 실제 게시판까지 확인
python notify.py              # 게시판마다 그 봇으로 테스트 메시지 발송

WATCH_MODE=new python watch.py    # 새 글만 (가볍다)
python watch.py                   # 수정까지 (기본)
python epic.py 목록.html           # 에픽에 로그인해 목록 화면만 저장
```

> `python epic.py` 는 로그인을 한 번 한다. 화면 구조가 바뀌어 파서를 고쳐야
> 할 때만 쓰고, 그냥 여러 번 돌리지 않는다.

## 게시판 추가·제거

`boards.json` 에 이름과 목록 주소를 넣는다. 같은 게시판 프로그램을 쓰는
과기대 게시판이면 파서를 고칠 필요가 없다.

```json
{
  "name": "취업정보",
  "url": "https://www.seoultech.ac.kr/...",
  "bot": "KAKAOWORK_APP_KEY_JOBS"
}
```

`bot` 은 **앱키가 아니라 앱키가 들어 있는 Secret 의 이름**이다. 앱키를 이 파일에
적으면 저장소에 그대로 올라간다. 생략하면 공용 봇(`KAKAOWORK_APP_KEY`)을 쓴다.

전용 봇을 쓰려면 두 곳에 더 손대야 한다.

1. 깃허브 Secrets 에 `KAKAOWORK_APP_KEY_JOBS` 등록
2. `.github/workflows/watch.yml` 의 `env:` 에 한 줄 추가
   ```yaml
   KAKAOWORK_APP_KEY_JOBS: ${{ secrets.KAKAOWORK_APP_KEY_JOBS }}
   ```
   깃허브는 이름을 나열해 준 Secret 만 넘겨준다. 빠뜨리면 조용히 공용 봇으로
   나가므로, 실행 로그에 `... 가 비어 공용 봇으로 보냅니다` 가 있는지 본다.

게시판을 지우면 `state.json` 의 해당 항목도 지워야 깔끔하다 (안 지워도 무해하다).

## 언제 얼마나 자주 도나

확인을 두 가지로 나눴다. **새 글 확인**은 목록만 받으므로 게시판당 접속이
한 번이다. 자주 돌려도 학교 서버에 부담이 없다. **수정 확인**은 게시물
상세를 전부 다시 읽어야 해서 게시판당 스물몇 번이라 하루 두 번만 돈다.

| 한국 시간 | 확인 | 주기 |
|---|---|---|
| **평일 09:00~12:00** | 새 글 | **5분** — 공지가 몰리는 시간 |
| 주말 09:00~12:00 | 새 글 | 15분 |
| 매일 08:00~09:00, 12:00~21:00 | 새 글 | 15분 |
| 매일 21:00~08:00 | 새 글 | 1시간 |
| 매일 13:07, 22:07 | 수정까지 | 하루 2번 |
| 에픽폴리오 | 새 프로그램만 | **최소 3시간 간격** |

에픽폴리오는 위 일정이 깨워도 3시간이 안 지났으면 건너뛴다
(`boards.json` 의 `min_interval_min`). 로그인해서 보는 곳이라 자주 두드리면
봇으로 몰려 계정이 막힐 수 있다.

5분이 깃허브가 허용하는 가장 짧은 주기다. 그마저도 깃허브가 바쁘면 몇 분
늦게 돈다. 정확히 5분마다는 아니다.

바꾸려면 `.github/workflows/watch.yml` 의 `cron` 을 고친다. **시각은 전부
UTC 다** — 한국 시간에서 9를 빼면 된다. 수정 확인을 맡는 줄(`7 4,13 * * *`)은
워크플로 안에서 이름으로 구분하므로, 그 줄을 고치면 아래 `WATCH_MODE` 줄의
비교 대상도 같이 고쳐야 한다.

손으로 돌릴 때는 Actions 탭 → **Run workflow** → `new` / `full` 을 고른다.

## 자주 겪는 문제

**알림이 안 온다** — Actions 탭에서 실행 로그를 본다. `보내지 못했습니다` 면
Secrets 가 안 들어간 것이다. `'...' 를 못 찾았습니다` 면
`KAKAOWORK_USER_EMAIL` 이 카카오워크에 등록된 이메일과 다르다.

**같은 알림이 계속 온다** — 알림 전송은 됐는데 `state.json` 커밋이 실패했을
가능성이 크다. 워크플로의 `permissions: contents: write` 가 살아 있는지,
저장소 Settings → Actions → General → Workflow permissions 가
**Read and write** 인지 확인한다.

**`목록에서 게시물을 하나도 못 찾았습니다`** — 학교가 게시판 HTML 구조를 바꿨다.
`watch.py` 의 `_LINK_RE`, `_BODY_RE` 를 실제 페이지에 맞춰 고쳐야 한다.

**예약 실행이 멈췄다** — 깃허브는 저장소에 60일간 아무 활동이 없으면 예약
워크플로를 자동으로 끈다. 이 프로그램은 공지가 바뀔 때마다 `state.json` 을
커밋하므로 보통 저절로 유지된다. 그래도 멈췄다면 Actions 탭에서 다시 켜면 된다.

## 에픽폴리오 (로그인이 필요한 곳)

다른 셋과 다르게 다룬다.

* **새 프로그램만 본다.** 상세를 열지 않으므로 프로그램 내용이 바뀌는 것은
  모른다(그래도 된다는 요청).
* **프로그램을 제목으로 구분한다.** 목록의 `encSddpbSeq` 는 이름 그대로
  암호화된 값이라 세션마다 달라질 수 있다. 그걸 열쇠로 삼았다가 값이 바뀌면
  매 실행이 '전부 새 프로그램' 이 되어 알림이 쏟아진다.
* **최소 3시간 간격.** 로그인하는 접속이라 자주 두드리면 봇으로 몰린다.
* **로그인 실패 시 재시도하지 않는다.** 연속 실패는 계정 잠금으로 이어진다.
  다음 실행 때 한 번 더 해보는 것으로 충분하다.

로그인은 브라우저 없이 통과한다. 로그인 창의 자바스크립트가 하는 일을 그대로
따라 한다 — RSA 로 아이디·비밀번호를 싸서 서버에 넘기고(암호화는 파이썬 기본
기능 `pow` 로 한다), 포털이 돌려주는 **자동 제출 폼**을 대신 보낸다. 이 마지막
한 단계가 빠져서 처음에 로그인이 안 됐다. 브라우저는 그 폼을 자바스크립트로
곧바로 다시 보내는데, 우리는 자바스크립트를 돌리지 않기 때문이다.

로그인에 17초쯤 걸린다. 사람이 브라우저로 해도 15초 걸리는 곳이다.

`EPIC_ID` / `EPIC_PW` 는 학교 **통합 계정**이라 성적·개인정보까지 열리는
열쇠다. `.env` 에만 두고(커밋되지 않는다) 깃허브에는 Secrets 로 넣는다.
